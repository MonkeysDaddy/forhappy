## 1. 产品概述

### 1.1 产品定位

ForHappy 是一款**以效率为核心**的单身交友 App。用户画像、玩法和商业化都服从一个目标：

> **让用户在最少的操作步数内，完成「看到 → 心动 → 配对 → 开口聊天」这条链路。**

不做直播、不做广场动态、不做虚拟礼物（至少在 MVP 和 M1 阶段）。所有偏离主链路的功能都视为噪音。

### 1.2 目标用户

| 维度 | 描述 |
|---|---|
| 年龄 | 20–35 岁单身人群，核心 22–30 岁 |
| 诉求 | 认真交友/恋爱导向，目的明确，不愿在"泛社交"里耗费时间 |
| 场景 | 通勤、午休、睡前等碎片时间浏览卡片；周末线下见面 |
| 心理特征 | 反感套路、反感机器人、反感"充值才能说话"；对真实性和效率敏感 |

### 1.3 核心设计原则

1. **简单（Simple）**：主路径每一步都是单次决策。注册 ≤3 分钟进发现页；浏览即瀑布流卡片，喜欢只需一次点击，无复杂手势学习成本。
2. **快速（Fast）**：
   - 找得快：人员卡片按位置排列、城市可切换，一打开就是目标人群；
   - 匹配快：喜欢即时反馈，配对即时推送；
   - 开口快：配对成功后提供破冰话术/共同点提示，消灭"在吗"式尬聊；
   - 反馈快：所有操作（点赞、发消息）零等待感，离线乐观更新。
3. **可信（Trust）**：真人认证 + 内容审核 + 举报闭环。交友产品的生死线是"这里的人是真的"。
4. **体验对等（Fairness）**：女性体验决定产品天花板。防骚扰机制（先配对后聊天、举报即时生效）优先级高于男性侧的"效率功能"。

### 1.4 商业模式：VIP / SVIP 订阅

双档会员订阅是 ForHappy 的主要收入来源（详细设计见 4.8–4.9，M1 上线）：

- **VIP**：解锁「查看谁喜欢了我」、无限喜欢、反悔、仅看已认证等体验增强；
- **SVIP**：含全部 VIP 权益，另加高级筛选（学历/职业/兴趣）、推荐优先曝光、隐身访问、超级喜欢等；
- **定价机制**：VIP / SVIP 的金额全部由管理后台动态配置（商品上下架、售价、活动首购价），客户端实时拉取，**不硬编码价格**；
- 付费红线：**付费只卖效率与曝光，不出售"聊天权"**——浏览/喜欢/配对/聊天主链路永久免费。"付钱才能发消息"的模型会迅速劣化女性体验（他趣的教训）。

## 2. 竞品分析

### 2.1 对标产品

| 产品 | 核心模式 | 值得借鉴 | 需要规避 |
|---|---|---|---|
| **Tinder** | 滑动卡片 + 互相喜欢才能聊天 | ① 滑动交互是效率天花板，已成用户心智；② 互相喜欢制天然防骚扰；③ 资料极简，决策成本低 | 付费墙过重（不看谁喜欢我就得盲刷）；国内无法本土化落地 |
| **探探** | 中国版 Tinder | ① 真人头像认证体系；② 本地化合规流程完整；③ 暗恋/擦肩而过等本地化玩法 | 商业化过重，普通男性用户体验持续劣化；假人/营销号治理口碑差 |
| **他趣** | 聊天导向 + 语音房/直播 | ① 破冰玩法丰富（真心话、语音速配），降低开口成本；② 聊天意愿强 | 功能臃肿偏离交友本质；陪聊/礼物模式让关系变味 |
| **Soul** | 兴趣图谱 + 灵魂匹配 | ① 兴趣标签匹配可作为外貌之外的第二维度 | 匹配链路长、效率低，与"快速"目标冲突 |

### 2.2 ForHappy 的差异化机会

头部产品的共同痛点恰好是 ForHappy 的切入点：

1. **"机器人/假人太多"** → 全量真人认证 + 真人担保的干净卡片池，作为第一卖点。
2. **"匹配了也不知道聊什么"** → 配对页直接展示双方共同点（同城、同兴趣、同校/同行业），并生成破冰建议。
3. **"刷了很久什么都没有"** → 冷启动算法向新用户倾斜曝光，保证前 30 分钟内必有可互动对象。
4. **"不充钱就没法用"** → 主链路（浏览/喜欢/配对/聊天）永久免费；会员只卖效率与曝光（见 4.8），没有"付费聊天"。

**定位一句话：基于位置的人员卡片信息流 + 更干净的真人池子 + 更快的开口体验。**

## 3. 核心用户流程

### 3.1 主链路（黄金路径）

```
下载打开
  │
  ▼
手机号一键登录/验证码登录          [步骤 1]
  │
  ▼
选择性别 + 想看谁（男/女/都看）     [步骤 2]  ← 决定卡片池，必须在首次进入前完成
  │
  ▼
上传照片（≥1 张，建议 3–6 张）      [步骤 3]  ← 机器审核秒级反馈
  │
  ▼
填写昵称 / 生日 / 所在城市           [步骤 4]  ← 仅必填项，其余可跳过
  │
  ▼
进入发现页（首页）                   [步骤 5]  ← 注册到浏览 ≤ 3 分钟
  │    （瀑布流/列表可切换，默认按位置排列，可切换城市）
  ▼
点击卡片上的 ❤ 喜欢 / 进详情页喜欢
  │
  ├─ 对方也喜欢我 ──► 配对成功弹窗 ──► [发消息] 或 [继续逛]
  │                        │
  │                        ▼
  │                   聊天页（破冰提示 + 共同点）
  │                        │
  │                        ▼
  │                   交换联系方式 / 线下见面
  │
  └─ 单向喜欢 ──► 进入"喜欢我的人"模糊墙（VIP 查看完整列表，见 4.8）
```

### 3.2 关键设计决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 聊天门槛 | **互相喜欢后才能聊天** | 防骚扰的根本手段；他趣式"任何人可打招呼"会引入大量垃圾消息，伤害女性留存 |
| 注册必填项 | 性别倾向 + 1 张过审照片 + 昵称 + 生日 + 城市 | 少于这 5 项匹配质量崩塌，多于这 5 项注册转化崩塌 |
| 位置获取 | 首次进入发现页时请求 | 距离是位置排序的第一依据；拒绝授权时降级为手动选城市，不影响基础浏览 |
| 照片审核时机 | 上传即异步审核，通过才计入资料 | 不让违规照片进入卡片池；审核失败即时给出原因和重传入口 |

## 4. 功能设计（PRD）

优先级定义：**P0 = MVP 必须 / P1 = M1 迭代 / P2 = 远期**

### 4.1 注册与登录

| 功能 | 说明 | 优先级 |
|---|---|---|
| 手机号验证码登录 | 60s 防重发、每日同号码上限 10 条；未注册号码自动注册 | P0 |
| 本机号码一键登录 | 运营商免密登录（极光/阿里云号码认证），注册转化可提升 20%+ | P1 |
| 首次引导三问 | 性别 / 想看谁 / 出生年份（校验 ≥18 岁） | P0 |
| 未成年人拦截 | 年龄 <18 直接拒绝注册并提示 | P0 |

### 4.2 个人资料

**必填（注册流程内）**

| 字段 | 规则 |
|---|---|
| 照片 | ≥1 张过审；建议 3–6 张；第一张为头像（卡片主图） |
| 昵称 | 2–12 字符，过敏感词；不允许纯联系方式（微信号/手机号正则拦截） |
| 生日 | 用于年龄展示与匹配区间，注册后不可改（防伪造） |
| 城市 | 定位自动获取，可手动修改 |

**选填（资料完善度引导，影响曝光权重）**

身高、学历、职业、行业、兴趣标签（从预置词库多选，≤8 个）、自我介绍（≤200 字）、感情状态（认真交友/先交朋友看发展）。

**照片规范（审核与展示）**

- 至少 1 张清晰真人正面照；系统对"无脸/远景/明星网图/二维码/水印占比高"的图片自动拒审并说明原因；
- 资料页照片全屏沉浸式浏览（左滑切换，对标探探）；
- 支持拖动排序、设为头像、删除（至少保留 1 张过审照片）。

### 4.3 发现（人员卡片瀑布流 / 列表）—— 产品心脏

**展示形态（可切换）**

| 形态 | 布局 | 卡片内容 | 适用场景 |
|---|---|---|---|
| 瀑布流（默认） | 双列错落卡片，主图 3:4 | 照片 + 昵称 + 年龄 + 距离 + 认证角标 | 快速浏览、眼缘决策 |
| 列表 | 单列大卡片 | 照片（左）+ 昵称/年龄/城市/距离 + 一句话简介 + 兴趣标签（≤3） | 信息决策、减少误触 |

- 页顶分段控件切换形态，记住用户选择（本地设置）；
- 点击卡片 → 资料详情页；瀑布流卡片右下角与列表卡片右侧均有 ❤ 快捷喜欢按钮（单击即喜欢，即时配对判定）；长按或卡片右上角 × = 隐藏（不感兴趣）；
- 瀑布流图片按宽高比占位防跳动，触底前预加载下一页，滚动帧率目标 60fps。

**排序（支持基于位置排列）**

| 排序 | 规则 | 说明 |
|---|---|---|
| 距离优先（默认） | 按与我直线距离升序；同距离档位内按活跃度分排列 | 需定位权限；拒绝授权时降级为"城市中心距离"或推荐排序并提示 |
| 推荐优先 | 综合推荐分（见第 5 章） | 个性化混排，最大化双向互动概率 |
| 最近活跃 | 按最后活跃时间倒序 | 低密度城市兜底，避免看到"死"用户 |

**筛选**

| 筛选项 | 规则 | 权限 |
|---|---|---|
| 城市 | 默认当前城市（定位或资料城市），省市选择器可切换任意城市浏览 | 免费 |
| 年龄区间 | 默认 20–32 | 免费 |
| 距离上限 | 1–100km，默认 30km，仅"当前城市 + 距离排序"下生效 | 免费 |
| 只看已认证 | 仅展示完成真人认证的用户 | VIP |
| 学历 / 职业 / 兴趣 | 高级组合筛选 | SVIP |

- 切换到其他城市后，距离基准改为该城市中心点，卡片距离显示"距市中心约 x km"；
- 筛选条件 + 排序 + 展示形态变更时重置分页重新请求（见 9.3 feed 接口）。

**配额与限制**

| 规则 | 策略 |
|---|---|
| 每日喜欢次数 | 免费默认 30 次/日（后台可配置，冷启动期可设为不限）；VIP/SVIP 无限 |
| 隐藏（不感兴趣） | 不限次；被隐藏用户不再出现 |
| 反悔（撤销最近一次喜欢/隐藏） | VIP 每日 5 次，SVIP 不限 |
| 信息流空态 | 引导放宽年龄/距离、切换城市，或提示"稍后再来" |

**详情页（点开卡片后）**

照片轮播 → 基本信息（年龄/城市/身高/学历/职业）→ 兴趣标签 → 自我介绍 → 底部喜欢/隐藏按钮。若有共同点（共同兴趣、同城同区），在顶部以胶囊标签突出展示。

### 4.4 配对（Match）

- **互相喜欢即刻配对**：当我喜欢了一个已经喜欢我的人，服务端返回 `matched=true`，客户端弹出配对成功页（双方照片拼合 + 动效）；
- 配对成功页按钮：**[发消息]**（直达聊天页）/ **[继续逛]**；
- 配对即时推送：若对方 App 在后台，走厂商通道/三方推送提醒"有人和你配对成功"（推送文案不带隐私信息）；
- 解除配对：任一方可在聊天页或配对列表中解除，双向静默移除（不通知对方），会话消息对双方隐藏。

### 4.5 消息（聊天）

**会话模型**：一个配对 = 一个会话。解除配对会话归档。

| 功能 | 说明 | 优先级 |
|---|---|---|
| 文本消息 | ≤500 字；敏感词机审（异步，命中高风险撤回并提示） | P0 |
| 图片消息 | ≤9 张/条逻辑；上传前本地压缩；过机审后投递 | P0 |
| 破冰提示 | 新会话首屏展示 3 条破冰建议（基于共同点生成，见 4.6），点击即发送 | P0 |
| 已读回执 | 展示"已送达/已读" | P1 |
| 输入中状态 | "对方正在输入…" | P1 |
| 未读角标 | Tab 级与会话级未读数 | P0 |
| 消息撤回 | 2 分钟内可撤回 | P1 |
| 安全提醒条 | 会话顶部常驻："谨防财物往来，线下见面选择公共场所" + 举报入口 | P0 |

### 4.6 破冰与共同点（差异化功能）

配对成功时，服务端计算双方交集并落库到 match 记录：

- **共同点标签**：共同兴趣、同城市、同行业、年龄相近、都完成了真人认证等，取最多 3 条；
- **破冰话术**：MVP 用模板 + 槽位填充（例："你们都喜欢「露营」，上次去哪儿玩的？"），按共同点选模板随机一条展示 3 条；
- **P2 演进**：接入 LLM 基于双方资料生成个性化开场白（一键发送，可换一批）。

### 4.7 个人中心与设置

| 功能 | 优先级 |
|---|---|
| 编辑资料（照片/选填项） | P0 |
| 我的配对列表 | P0 |
| 会员中心（权益对比/收银台/订单与续费管理，见 4.8） | P1 |
| 喜欢我的人（模糊头像墙，VIP 解锁完整列表） | P1 |
| 账号与安全：注销账号（7 天冷静期 + 硬删除策略见 6.4） | P0 |
| 隐私：隐藏距离/隐身模式 | P1 |
| 黑名单管理 | P0 |
| 推送开关 | P0 |

### 4.8 会员体系（VIP / SVIP）

**设计原则**

1. 主链路永久免费：浏览、喜欢、配对、聊天全程不收费；会员只卖**效率与曝光**；
2. **金额全部后台动态配置**：客户端不硬编码任何价格，收银台实时拉取 `/member/products` 渲染；运营改价、上活动、上下架无需发版；
3. SVIP 涵盖全部 VIP 权益（高档含低档），同时订阅时按时长叠加、档位取高。

**权益矩阵**

| 权益 | 免费用户 | VIP | SVIP |
|---|---|---|---|
| 每日喜欢次数 | 30 次/日（后台可配置，冷启动期可设为不限） | 无限 | 无限 |
| 反悔（撤销最近一次喜欢/隐藏） | 不支持 | 每日 5 次 | 不限 |
| 查看谁喜欢了我 | 模糊头像墙 | 完整列表 | 完整列表 + 在线优先展示 |
| 筛选器 | 城市 / 年龄 / 距离 | + 只看已认证 | + 学历 / 职业 / 兴趣（高级筛选） |
| 推荐优先曝光 | — | — | 推荐排序加权 |
| 隐身访问（看资料不留痕迹） | — | — | ✓ |
| 超级喜欢（高亮展示给对方） | — | 每日 1 次 | 每日 5 次 |
| 资料标识 | 真人认证角标 | VIP 徽章 | SVIP 专属徽章 + 头像框 |
| 消息已读回执 | — | ✓ | ✓ |

> 权益矩阵以「权益码 → 是否启用/配额」存于后台配置表，客户端展示与服务端判定读同一份快照，防止客户端篡改配额。

**商品与定价（后台配置）**

| 商品 | 时长 | 金额 | 说明 |
|---|---|---|---|
| VIP 月卡 | 30 天 | 后台配置 | 锚点商品，可设首购优惠价 |
| VIP 季卡 | 90 天 | 后台配置 | 展示折扣角标（折算月卡价对比） |
| VIP 年卡 | 365 天 | 后台配置 | 日均成本最低，主推位 |
| SVIP 月/季/年卡 | 同上 | 后台配置 | 定价建议为 VIP 的 1.8–2.5 倍 |

- 金额以**分**为单位配置，含：售价、划线原价、首购活动价（可为空）；
- 改价只影响新订单；订单创建时对价格做**快照**，避免改价引起争议；
- iOS 端金额需映射到 Apple IAP 价格档（平台规则，见 4.9），Android 端微信/支付宝支持任意分级定价。

**付费触点（运营位设计）**

- 免费喜欢配额用尽 → 弹窗引导收银台（主转化入口）；
- "喜欢我的人"模糊墙 → "开通 VIP 查看完整列表"；
- 点击高级筛选项（学历/职业/兴趣）→ SVIP 引导；
- 被动入口：我的页会员中心；
- 频控：主动付费弹窗每用户每日 ≤1 次，避免打扰伤害留存。

### 4.9 支付与订阅生命周期

**支付渠道**

| 渠道 | 适用 | 说明 |
|---|---|---|
| 微信支付 | Android | 支持签约代扣（自动续费） |
| 支付宝 | Android | 支持签约代扣（自动续费） |
| Apple IAP | iOS | 虚拟商品强制走 IAP；使用自动续期订阅（Auto-Renewable Subscription），续费生命周期由 Apple 管理，平台抽成计入定价 |

**订阅与续费**

- Android 自动续费：签约代扣协议，到期前 24h 发起扣款，失败重试最多 3 次（间隔 6h/24h/48h），全部失败则权益到期降级；
- iOS 自动续费：监听 Apple Server Notification（DID_RENEW / EXPIRED / REFUND 等）+ 登录时票据校验兜底；
- 续费/新订价格以扣款时刻的后台配置为准（订单快照）。

**权益开通与判定**

- 开通流程：支付回调验签通过 → 订单置已支付 → `membership` 延期（续费在现有到期时间上叠加，新订从当前时间起算）→ 失效权益缓存 → 推送"开通成功"；

**退款与风控**

- 收到第三方退款回调 → 即时收回权益 + 订单标记退款 + 风控记录；
- 12 个月内退款 ≥2 次 → 冻结订阅功能（仍可浏览，不可再订阅）；
- 对账：每日定时对账（订单表 ↔ 渠道账单），差错生成工单人工处理。

**后台管理（admin）**

- 商品管理：上下架、改价、设置划线价与首购活动价（改价即时生效于新订单）；
- 权益配置：权益码与配额的矩阵调整；
- 订单查询 / 手动补偿开通（运营赠卡，必须留操作日志与审批人）；
- 营收看板：订阅数、续费率、收入分渠道统计（见 10.5）。

## 5. 匹配与推荐算法

### 5.1 排序模式与目标函数

发现页支持三种排序（见 4.3），算法负责"推荐优先"的打分，并为"距离优先"提供档内排序：

| 排序 | 逻辑 |
|---|---|
| 距离优先（默认） | 硬过滤 → Redis GEO 距离升序，同距离档位内按活跃度分排序（避免最近的几个人固化霸屏） |
| 推荐优先 | 按下方综合分排序，最大化双向互动概率 |
| 最近活跃 | 按 last_active_at 倒序 |

推荐排序的目标不是"把最好看的人排最前"，而是**最大化双向互动概率**：

```
score(A→B) = w1·距离分 + w2·偏好匹配分 + w3·活跃度分 + w4·互动先验分 - 惩罚项
```

### 5.2 因子拆解（MVP 简化版）

| 因子 | 计算 | 权重建议 |
|---|---|---|
| 距离分 | 1 - dist/max_dist，同城优先 | 0.35 |
| 偏好匹配 | B 是否落在 A 的年龄/距离筛选内（硬过滤），兴趣标签交集数 | 0.25 |
| 活跃度分 | 近 7 日活跃天数归一化；**超过 14 天未活跃的用户降权或移出队列**（防止信息流出现"死"用户） | 0.20 |
| 互动先验（Elo） | 类 Tinder Elo：被喜欢率高的用户得分高；互相喜欢成功 +分，被隐藏 -分（男女分池计算，防止头部用户垄断） | 0.20 |

**惩罚项**：被举报率高的用户降权直至封禁；新注册未认证用户在认证用户池外单独排队（见 5.4）。

### 5.3 信息流生成策略

1. **硬过滤**（所有排序模式共用）：性别倾向互斥过滤、年龄/城市筛选、黑名单互斥、已喜欢/已隐藏的人不再出现（解除配对的人 30 天内不再出现）；
2. **排序**：距离优先直接用 GEO 查询结果；推荐优先按 5.1 打分取 TopN；
3. **多样性注入**（推荐优先）：每页 20 条中保证 ≥20% 为"分数带外"用户，避免信息茧房和头部垄断；
4. **新用户保护**：新注册用户前 24 小时获得 3 倍曝光加权（男女均适用），保证冷启动体验；
5. **性别比例调控**：某性别池严重过剩时（如男:女 > 4:1），对过剩性别的新曝光做节流，优先把稀缺性别曝光给高质量活跃用户。

### 5.4 认证分层池

- **已真人认证池** 与 **未认证池** 分开推荐。认证用户优先看认证用户；
- 未认证用户可以在信息流中看到认证用户，但其喜欢以"低权重"进入对方推荐队列（对方大概率看不到他）——用曝光激励用户完成认证。

### 5.5 技术实现

- 距离优先：Redis `GEORADIUS` 实时分页查询 + MySQL 精筛条件，无预计算，响应 <50ms；
- 推荐优先：MySQL 定时任务（每 10 分钟）批量生成候选集 → 写入 Redis 的每用户候选队列（ZSET，score 排序）→ feed 接口按游标读取，零计算；
- feed 统一游标分页（lastId + lastScore），客户端瀑布流增量加载、切排序/筛选时重置游标；
- M1 起：引入实时特征（刚活跃、刚认证）做增量补丁；Elo 分数用 Redis 维护，每日批量重算。

## 6. 安全、信任与合规

### 6.1 内容审核（机器为主，人工兜底）

| 对象 | 方案 | 时机 |
|---|---|---|
| 照片 | 云厂商图片审核 API（涉黄/涉政/广告二维码/敏感场景）+ 人脸检测（无脸拒审） | 上传即审，阻塞展示 |
| 昵称/简介 | 文本审核 API + 自定义敏感词库 + 联系方式正则（微信/QQ/手机号变体） | 提交即审 |

| 聊天图片 | 先审后投（或先投后撤，MVP 采用先投后撤降低延迟，高风险 30s 内撤回） | 发送后异步 |

### 6.2 真人认证（P1，但强烈建议尽早）

- 方案：活体检测 + 人脸与头像比对（腾讯云人脸核身/阿里云实人认证）；
- 通过后头像角标展示"已认证"徽章，进入认证推荐池；
- 认证资料永久留存证据链（加密存储），配合公安调证。

### 6.3 举报与屏蔽

- 举报入口：用户资料页、聊天页右上角；
- 举报类目：虚假资料 / 诈骗引流 / 骚扰辱骂 / 色情低俗 / 疑似未成年 / 其他；
- 支持勾选聊天记录作为证据（一键附带最近 20 条）；
- **屏蔽即时生效**：双向从发现信息流移除、会话关闭、对方无法通过任何路径再次触达；
- 处置 SLA：机器预判 + 人工复核，高风险（涉诈/未成年）2 小时内处置；处置结果反馈举报人；
- 累计处罚阶梯：警告 → 限流 → 禁言 → 封号（设备指纹 + 手机号拉黑，防小号复活）。

## 10. 指标体系与数据埋点

### 10.1 北极星指标

**每周新增「双向开口」配对数**：配对成功且双方在 24 小时内互发 ≥1 条消息。
（比单纯配对数更抗刷量，直接衡量"找到了能聊的人"这一核心价值。）

```
下载 → 注册成功 → 资料过审 → 首次浏览 → 首次喜欢 → 首次配对 → 首条消息 → 收到回复
        (目标>70%)  (>85%)    (>90%)
```

### 10.3 分角色看板

| 指标 | 说明 | 健康线参考 |
|---|---|---|
| 次日/7日留存 | 分性别看，女性留存是生死线 | 次留 >40% |
| 喜欢率 = 喜欢数/卡片曝光数 | 男女分别统计；男高女低是常态，差距过大说明池子失衡 | 女 5–15%，男 30–60% |
| 配对率 = 配对数/喜欢数 | 分性别 | 女 >25% |
| 首消息发送率 | 配对后 24h 内 | >50% |
| 回复率 | 收到首消息后 24h 内回复 | >40% |
| 人均日浏览卡片数 | 体验黏性 | 50–150 |
| 付费墙转化率 | 配额用尽弹窗 → 收银台 → 支付成功 | 见 10.5 |
| 举报率 / 封号率 | 安全水位 | 举报率 <0.5% DAU |

## 11. MVP 范围与迭代路线图

### 11.1 MVP（M0）—— 验证闭环

**范围 = 第 4 章所有 P0**：登录注册 → 资料与照片（机审）→ 发现页浏览（瀑布流/列表、位置排序 + 城市/年龄筛选）→ 互相喜欢配对 → 文本/图片聊天（含破冰提示）→ 举报屏蔽 → 注销。

**明确不做**：会员收费开通（权益框架与配额开关预埋，免费全放开，M1 开订阅）、超级喜欢、真人认证（用人工抽审照片过渡）、动态广场、直播、语音。

**验证假设**：
1. 注册→首次浏览转化 ≥70%；
2. 女性 7 日留存 ≥30%；
3. 北极星指标（双向开口配对）周环比增长。

### 11.2 路线图

| 阶段 | 主题 | 关键内容 |
|---|---|---|
| M0 | 验证闭环 | 上文 MVP 范围（含会员配额开关与权益框架预埋，免费全放开）；单城市/小圈子冷启动 |
| M1 | 信任 + 商业化基础 | 真人认证（人脸核身）、一键登录、推送召回策略、Elo 正式版；**VIP/SVIP 上线**：后台金额配置、微信/支付宝代扣与 Apple IAP、"谁喜欢了我/无限喜欢/反悔/高级筛选"等权益（见 4.8–4.9） |
| M2 | 商业化增强 | 超级喜欢、Boost 曝光、首购/折扣活动体系、SVIP 隐身访问与优先曝光调优；LLM 破冰 |
| M3 | 关系深化 | 语音消息/语音速配、线下活动（同城组局）、动态广场（谨慎评估） |

### 11.3 冷启动策略（产品之外但决定成败）

- **单点破局**：只做一个城市，甚至一个圈子（如某几所高校/某个行业社群），把局部密度做透再扩张；
- **邀请制 + 种子用户**：首批 500–1000 人人工审核资料，保证池子质量口碑；
- **女性优先运营**：女性体验（防骚扰响应速度、资料审核严格度）作为冷启动期唯一 KPI。

## 12. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
